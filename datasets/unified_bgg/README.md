# unified_bgg

`unified_bgg` is the planning and build workspace for a unified BoardGameGeek dataset. It integrates the seven local public datasets under `research/datasets/` into a traceable data foundation for board-game model fine-tuning and RAG retrieval.

## Current phase

Phase 10 expanded retrieval evaluation is now generated and validated. Phase 1 inventory/schema work, Phase 2 BGG-ID alignment, Phase 3 core intermediate tables, Phase 4 taxonomy canonicalization, Phase 5 RAG samples/review digests, Phase 6 quality/FTS index, Phase 7 taxonomy and finetune candidates, Phase 8 hybrid retrieval, and Phase 9 unified retrieval interface are complete. The 26M-row BGG rating/review CSV has been streamed to create local extractive review digests; full row-level `ratings` and `reviews` tables are still not materialized by default.

## Recommended flow

1. Run `python scripts/profile_sources.py` to refresh inventory files.
2. Run `python scripts/build_id_map.py` to refresh ID profiles and `intermediate/id_map.csv`.
3. Run `python scripts/build_core_tables.py` to refresh `games`, `game_stats`, and `game_taxonomy`.
4. Run `python scripts/build_taxonomy_aliases.py` to refresh `taxonomy_aliases.csv` and `game_taxonomy_canonical.csv`.
5. Run `python scripts/build_rag_samples.py` to refresh `samples/rag/game_overview*.jsonl` and `samples/rag/mechanic_profile*.jsonl`.
6. Run `python scripts/build_review_digest.py` to stream `bgg-26m-reviews.csv` and refresh `samples/rag/review_digest*.jsonl`.
7. Run `python scripts/smoke_test_rag_retrieval.py` to verify local lexical retrieval over generated RAG docs.
8. Run `python scripts/evaluate_rag_quality.py` to audit generated RAG JSONL quality.
9. Run `python scripts/build_rag_index.py` to build `final/rag_index.sqlite`.
10. Run `python scripts/build_vector_index.py` to build `final/rag_vector_index.sqlite`.
11. Query locally with `python scripts/query_unified_index.py "Through the Ages civilization" --doc-type game_overview`.
12. Export a reusable retrieval suite with `python scripts/export_retrieval_suite.py --engine hybrid`.
13. Export the expanded Chinese retrieval suite with `python scripts/export_retrieval_suite_expanded.py --engine hybrid --limit 5 --candidate-limit 50`.
14. Materialize full row-level `ratings` and `reviews` tables only if downstream training/retrieval needs raw rows rather than per-game digests.

## Design principles

- Use official BGG game IDs as the entity alignment anchor; internal IDs use `bgg:{bgg_id}`.
- Time-sensitive fields such as ratings, ranks, and user counts must keep `snapshot_date` and `source_dataset`.
- Mechanic names are not stable across years; cross-snapshot analysis needs an alias/mapping table.
- `bgg-sujaykapadnis` is a strict subset of `bgg-gabrio`, so it must not be counted as independent evidence.
- Every derived fact should remain traceable to the source dataset, file, and transform rule.
