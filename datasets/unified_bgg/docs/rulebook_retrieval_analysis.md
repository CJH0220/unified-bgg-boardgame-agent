# 规则书召回分析

## 这批规则书语料的价值

- 规则书正文提供的是“怎么做”的信息，游戏简介提供“这是什么游戏”的信息，评论摘要提供“玩家实际怎么感受”的信息。
- 三者结合后，模型能同时学到：规则步骤、机制术语、体验特征，以及高频抱怨点。
- 对桌游方向微调来说，`rulebook_text` 特别适合训练“机制解释、回合流程、阶段结构、组件/结算规则”的长文本回答。

## 案例 1 分析：Through the Ages

- 这是一个典型的“文明构筑 + 长规则 + 复杂结算”案例。规则书中直接覆盖手册、设置、玩家区、科学/文化/军事板块、行动阶段和最终计分，因此召回非常适合做规则解释。
- 游戏简介补上了它的核心标签：文明、资源管理、科技、军事压力；评论摘要则明确指出它“很重、很长、要反复查规则”，说明这个文档对长文问答和规则检索很有帮助。
- 这类案例适合做成高价值训练样本：用户问“怎么玩”“战斗怎么结算”“科技/文化如何得分”时，模型有足够依据做准确回答。

## 案例 2 分析：Brass: Birmingham

- 这是一个更偏“动作清晰、机制密集、结算链条明确”的案例。规则书长度不长，但每一页信息密度很高，适合训练动作级别的召回。
- 游戏简介和评论摘要共同确认了它的核心体验：建路、贷款、市场、卖货、发展、Scout；玩家的争议点主要集中在“规则细节多、要记住很多例外、经常像在做账”。
- 这类样本对模型很有帮助，因为它能把“规则书解释”与“玩家口碑里的痛点”一起学进去，后续做问答或召回时更容易输出贴近玩家语言的回答。

## 现在的检索建议

- 如果你要验证规则书召回，请优先用 `scripts/query_rag_index.py`，并显式指定 `--doc-type rulebook_text` 和 `--bgg-id`。
- 当前这条链路比统一入口更稳，因为它直接打到 FTS 索引，不会被其他文档类型稀释。
- 这批语料已经够做第一版“规则理解 / 机制解释 / 热门评论摘要”的联合微调样本。

## 下一步建议

- 扩充到不只是看 top100 高分，而是把你最关心的桌游名单单独纳入。
- 为短文本或疑似图片型 PDF 再补更可靠的 OCR 或替代来源。
- 如果后面要做真正的桌游问答数据集，可以把规则书、简介、评论摘要合并成对齐样本。
